# Развернуть vibe-flow в проекте

Пользователь сам вызвал установку — это согласие на запись файлов в проект. Коммит и push — только по отдельному «да» (шаг 8).

## 1. Проверить проект

```bash
git rev-parse --show-toplevel && git rev-parse --git-dir --git-common-dir && git log --oneline -1 && git remote -v
```

- Нужны `bash`, `git`, `python3`. Windows без WSL/Git Bash не поддерживается — сказать прямо. Проверено на macOS; на Linux/WSL механизм рабочий, но не прогонялся — если что-то упадёт, сообщить автору пакета.
- **Сессия стоит в linked worktree** (git-dir ≠ git-common-dir) → ставить надо в главное дерево: взять путь `git-common-dir/..`.
- **Не git-репозиторий или нет коммитов** → спросить через `AskUserQuestion`: «Сделать `git init` и первый коммит?». Нет → остановиться. Да:
  1. `git init`, если нужно
  2. Дописать в `.gitignore` (создать, если нет) недостающее из стандартного набора под стек: `.env*`, `node_modules/`, `.venv/`, `venv/`, `__pycache__/`, `dist/`, `build/`, `.next/`, `.DS_Store`, `*.log`
  3. Показать пользователю, что войдёт в коммит: `git add -A --dry-run | head -50` и общее число файлов. Есть подозрительное (ключи, большие бинарники, дампы БД) — спросить, прежде чем коммитить
  4. `git add -A && git commit -m "[chore]: первый коммит"` — хука vibe-flow ещё нет, здесь это можно

## 2. Спросить одно решение

Через `AskUserQuestion` (один вопрос):
- **Финальный гейт перед push** — «Включить (Recommended)»: каждый push сначала проверяет агент `vibe-flow:release-gate` на Opus — это минуты и токены Opus на каждый push, зато код от любых моделей не уходит непроверенным. «Выключить»: можно включить позже строкой `GG_RELEASE_GATE=1` в `.gitguards.conf`.

## 3. Запустить установщик

```bash
bash "${CLAUDE_PLUGIN_ROOT}/scripts/init.sh" "<корень проекта>"            # гейт включён
bash "${CLAUDE_PLUGIN_ROOT}/scripts/init.sh" "<корень проекта>" --no-gate  # гейт выключен
```

Таймаут Bash — 600000: установщик прогоняет приёмочные тесты защиты. Код возврата не 0 или в выводе «провалено: N>0» — разобрать и сказать пользователю, не продолжать молча.

## 4. Проверить `.gitguards.conf`

Установщик определил стек сам. Прочитать файл и сверить с проектом:
- `GG_TEST_CMD` — команда, которой `git-safe-commit.sh` **дописывает список закоммиченных файлов** и ждёт прогона связанных с ними тестов (`npx vitest related --run`, `npx jest --findRelatedTests`). Такой в проекте нет — оставить пустой: тесты тогда гоняет агент `vibe-flow:test-runner`. Не ставить сюда `npm test` или `pytest`: с путями-аргументами они запустят не то
- `GG_TYPECHECK_CMD`, `GG_DEV_CMD` — реально существуют в проекте (scripts в package.json и т.п.)?
- `GG_WT_DIR` — каталог рабочих деревьев; пусто = `<папка проекта>-wt` рядом с проектом, для нового проекта это правильно. 🔴 Если у проекта уже есть деревья в другом месте (`git worktree list`) — вписать их каталог явно, иначе `wt-done.sh` их не увидит и штатно не снимет
- `GG_PROTECTED` — ветка, из которой деплоится прод (`main`/`master`)

Неверное — поправить в файле и сказать, что поправлено.

## 5. Заполнить раздел «Проект» в CLAUDE.md

Агенты vibe-flow берут факты о проекте отсюда. Изучить проект (manifest-файлы, структура, конфиги деплоя, БД, i18n) и вписать раздел **ВНЕ** блока `vibe-flow:begin/end` — сразу перед ним — между своими метками:

```markdown
<!-- vibe-flow:project:begin -->
## 🧩 Проект
- **Что это:** <одна фраза>
- **Стек:** <язык, фреймворк, версия>
- **БД:** <нет / Postgres (Supabase) с RLS / SQLite / …>
- **Деплой:** <нет / Vercel / Docker / …> · прод-ветка `<GG_PROTECTED>`
- **Команды:** тесты `<…>` · типы `<…>` · dev `<…>` · сборка `<…>`
- **Где что лежит:** <3–6 пунктов: точки входа, API, UI, общая логика, миграции>
- **i18n:** <нет / локали …>
- **Разграничение доступа:** <нет / роли … / арендаторы …>
<!-- vibe-flow:project:end -->
```

Только факты, проверенные по файлам. Не знаешь — «не определено», и сказать пользователю. Раздел уже есть → обновить устаревшее, не переписывать целиком.

## 6. Карта кода

Есть `node` → `node "${CLAUDE_PLUGIN_ROOT}/skills/architecture-map/gen-codemap.mjs"`, затем по скиллу `/vibe-flow:architecture-map` написать краткий `docs/codemap/ARCHITECTURE.md`. Нет `node` → только `ARCHITECTURE.md` по чтению проекта.

## 7. Подсказать пакеты и инструменты

- `vercel.json`, каталог `.vercel/` или зависимость `vercel` → пакет `vibe-flow-vercel` (монитор деплоя, логи): `/plugin install vibe-flow-vercel@vibe-school`
- каталог `supabase/` или зависимость `@supabase/supabase-js` → пакет `vibe-flow-supabase` (агент БД, миграции): `/plugin install vibe-flow-supabase@vibe-school`
- `gh` (GitHub CLI) нет → PR и мерж Claude сделать не сможет, будет давать ссылки. Поставить: https://cli.github.com → `gh auth login`
- `codex` в PATH → внешний критик плана работает; предупредить: **план и фрагменты кода уходят второму провайдеру (OpenAI)**. Нет → «Внешний критик плана не установлен — планы проверяют только ревьюеры Claude. Поставить: `npm i -g @openai/codex` и `codex login`»

## 8. Закоммитить установку — ОБЯЗАТЕЛЬНО, до перезапуска

🔴 Без этого коммита рабочие деревья (`scripts/wt-new.sh`) создаются от HEAD **без** скриптов, хуков и правил — flow в них не работает. Сказать это пользователю и спросить «да» на коммит:

```bash
git status --short     # показать пользователю
scripts/git-safe-commit.sh --message-file <файл> -- scripts githooks .claude/hooks .claude/settings.json .gitguards.conf CLAUDE.md docs/codemap .gitignore
```

(пути — только реально созданные/изменённые установкой; чужие незакоммиченные файлы пользователя не трогать). Сообщение: `[chore]: vibe-flow — защита git, гейт и правила`.

Отказ → не коммитить, но прямо предупредить: «рабочие деревья работать не будут, пока эти файлы не в коммите».

**Затем — push установки в прод-ветку (если есть remote).** Это инструменты, а не код продукта: ревьюить гейтом нечего, а после перезапуска сессии этот коммит станет «чужим». Поэтому push делает человек, без хуков — дать готовую команду:
- remote есть: `! git push -u origin <GG_PROTECTED> --no-verify`
- remote нет: сказать, что первый push (когда подключит GitHub) — той же командой; до этого гейт и барьеры push не с чем сравнивать

## 9. Отчёт

Формат release-note: ✅ что развёрнуто · 🎯 что изменилось в работе · 🧪 что попробовать. Обязательно:
- 🔴 **Перезапустите сессию Claude Code** — хук, запрещающий `git add`/`commit` в главном дереве, подхватывается при старте
- Как начинать задачу: описать её Claude — он заведёт рабочее дерево (`scripts/wt-new.sh <имя>`) и предложит открыть в нём новую сессию (`cd <путь> && claude`)
- Где правила: блок vibe-flow в `CLAUDE.md`; свои правила — вне его меток

## Обновление

«Обнови vibe-flow»:
```
/plugin marketplace update vibe-school
/plugin update vibe-flow@vibe-school          (и пакеты стека, если стоят)
```
затем перезапуск сессии и этот скилл с шага 3: установщик обновит скрипты и блок правил, `.gitguards.conf` и раздел «Проект» не тронет. Обновлённые файлы — закоммитить (шаг 8).
